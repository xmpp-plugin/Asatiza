# Completion Report

Use this structure after Execute and Close operations. For normal scoped code changes, use the Normal Scoped Change Summary below.

## Execute Summary

- Phase ID
- Status
- Current step
- Approval
- Outcome
- Active phase conflict check
- Readiness check result
- Implementation summary
- Files modified
- Files created
- Files deleted
- Purpose of each file change
- File-by-file change log
- Compact technical check results, excluding app launch/build unless explicitly requested
- Newly introduced issues fixed
- Pre-existing unrelated issues not fixed
- Commands unable to run and reason
- Existing components reused
- Approved new components
- API/model/platform/dependency changes
- Out-of-scope findings
- Ready for developer manual testing

## Close Summary

- Phase ID
- Final status
- Current step
- Approval
- Outcome
- Completion date
- Final implementation summary
- Final changed files
- Execute technical checks and results
- Reused technical evidence
- Developer manual-test confirmation
- Tested platforms/devices
- Known limitations
- Follow-up work
- Rollback guidance
- Phase file path
- Phase state/index update
- Local commit result, only when explicitly approved

## Normal Scoped Change Summary

- Implementation summary
- Files modified
- Files created
- Files deleted
- Short per-file change descriptions
- Compact checks performed
- Active phase status, if any
